# ブート

## 方式

ブート処理を実装するうえでいくつかの方法が考えられる:

1. OpenSBIやRustSBIなどの既存のSBI実装を利用する (例: Linux,FreeBSD)
2. ファームウェアなし(`-bios none`)でMモードで起動 (例: xv6-riscv)
3. 小さなSBI実装を自作する (例: Zephyr,NuttXの内蔵SBI)

今回は 2. OSが直接Mモードで起動する方式 で進める。

## Mモード、Sモード

そもそもMモードとかSモードとかなに?って話がある。

CPUは特権レベルというものがあり、「今どこまでの操作が許されてるか」というのがモードによって決まっている。RISC-Vだと M(Machine)モード/S(Supervisor)モード/U(User)モードの3つが定義されている。
じゃあこれはできることがなにが違うのか、というと、モードによって触ることができるCSRや使える命令、アクセス可能なメモリ領域が違ってくる。

CSR(Control and Status Register)というのは、CPUの設定とか状態を読み書きするための特別なレジスタのことで、このレジスタをいじることで特権モードにおける振る舞いを変更することができる。

CSRや命令はprefixでアクセス可能な最低の特権レベルを表す(例: `mstatus`と`sstatus`)。

こうやって権限を分離することでなにがうれしいかというと、たとえばユーザモードのコードでやらかしても影響範囲を限定できる。

## 起動

QEMUは `-bios none` のときリセットベクタ `0x1000` でa0 = mhartid、a1 = DTB(Device Tree Blob: ハードウェアの構成情報) のアドレスをセットしてから `0x80000000` にジャンプとなる。
このアドレスは固定値なので、リンカスクリプト側で開始位置のセクションがここになるようにしてやる(`.text.boot`という名前のセクションがここにくる)。

```ld
ENTRY(entry)

SECTIONS
{
    . = 0x80000000;

    .text : {
        KEEP(*(.text.boot)) /* <--- 先頭にくるように */
        *(.text .text.*)
    }
(...)
```

DTBがa1で渡ってくるのはQEMUを想定しているので今回は問題ないが、そうではないブートROMや前段のブートローダもあるかもしれないので、実機などでは注意が必要になる。

## Mモード -> Sモード

OSはMモードからSモードに行くまでに以下のようなことをやっている。

- スタックポインタを設定
- MPPをSモードに設定
- mretで飛ぶ先をkmain(カーネル本体のエントリポイント)に設定
- Sモードでのメモリアクセスを許可
- ページングを無効にした状態でSモードに入るように設定
- 例外と割り込みをSモードに委譲
- mret: 実際にSモードへ切り替える

このあたりでやっていることは、ようはSモードに切り替えるための準備をMモードのうちにしている。

### スタックポインタ

起動・リセット直後はスタックポインタ(spの値)は不定なので、明示的に設定してやる必要がある。

エントリポイントは余計なコードを生成させないために `@naked` をつけてインラインアセンブリで記述している。

```d
@section(".text.boot")
@naked noreturn entry()
{
    // スタックをセットする。
    // 今のところqemuで-smp 1を指定しているので、
    // mhartid: 0 でspは __stack_top から変わってない。
    __asm(`
        la sp, __stack_top  # スタックポインタに stack topのアドレスをセット
        csrr a0, mhartid
        slli t0, a0, 12     # a0 (mhartid) x 4096
        sub sp, sp, t0
        j start
    `, "");
```

ここでspに設定している `__stack_top` がどこからきているかというと、これはリンカスクリプトにある。

```ld
    .stack(NOLOAD) : ALIGN(16) {
        PROVIDE(__stack_bottom = .);
        . += 4096;  /* スタックは4KiB */
        PROVIDE(__stack_top = .);
    }
```

リンカスクリプトでは同時にスタック領域の確保も設定している。

軽く内容を説明すると、

- `NOLOAD`: スタックの初期値は不要なので、確保だけして値を埋めない
- `ALIGN(16)`: RISC-VのpsABIではspは常に16バイト境界に揃える決まりになっているので指定
- 同様に、RISC-VのpsABIでスタックは下方向に伸びる決まりなので最初にセットする値は `__stack_top`

という感じになっている。

次に見慣れない命令列が続いているのが気になっていると思われる:

```
        csrr a0, mhartid
        slli t0, a0, 12     # a0 (mhartid) x 4096
        sub sp, sp, t0
```

まず、 `csrr a0, mhartid` で自分が何番目のhartか?という情報をレジスタ `a0` に設定している。

hart(hardware thread)というのはソフトウェアからみた実行の流れ(レジスタの一式)の単位で、これはCPUコアやSMT(Intelのハイパースレッディングのようなやつ)ごとに振り分けられる。

次に `slli t0, a0, 12` `sub sp, sp, t0` でスタックポインタの値をスタックサイズ x hart番号だけ下にずらす。
今は `-smp 1` なのでこの操作は影響を与えないが、複数hartで起動するときどのhartも `0x80000000` から開始するので、スタックを壊さないようにspをhart単位で割り当てる必要がある。

同様に、ここでは `-smp 1` の段階でコードが書かれているので4096バイトしか確保していないが、複数hartにする場合は 4096 x hart数に広げる必要がある。

### MPP・mpec

次にMPP(Machine Previous Privilege)をSモードに設定する、ということをやっている。

```d
    clearCsr!"mstatus"(MSTATUS_MPP_MASK);
    setCsr!"mstatus"(MSTATUS_MPP_S);
```

MPPはMモードに切り替わる直前にどの特権モードにいたか、を記録する。これを記録することで割り込みや例外をMモードで処理したあとにもといたSモードやUモードに正しく復帰することができる。

実際にハンドラの処理が終わったときにモードを変更するのは `mret` を実行したときになる。mret自体は「モードをMPPに、pcをmepcにする」ということを行うだけなので、`mepc` の値にカーネルのエントリポイントにあたる関数を設定することでSモードのときの処理を書き分けている。

```d
    writeCsr!"mepc"(cast(ulong) &kmain);
```

### メモリアクセスとページングの無効化

OSをSモードで動かす準備はできたが、実はこのままではメモリにアクセスすると例外になってしまう。
そのため、明示的にSモードでのメモリアクセスを許可する必要がある。

```d
    writeCsr!"pmpaddr0"(0x3f_ffff_ffff_ffffUL);
    writeCsr!"pmpcfg0"(PMP_A_TOR | PMP_R | PMP_W | PMP_X);
```

同時に、ページングを無効にする。

```d
    writeCsr!"satp"(0);
```

satpというのはアドレス変換を有効にするか?という設定、つまりページングの設定を行うものである。
satpの初期値は不定になっていて、起動時に有効状態・でたらめなページテーブルのアドレスが設定されている可能性もある。
Sモードに移行した瞬間にkmainの最初の命令をフェッチ->でたらめなページテーブルを引いてページフォルトが起きてしまう、といったことが起きるかもしれない。
そういったことを避けるために、明示的にsatp=0に設定しておくことでSモードでもアドレスは物理アドレスとして扱う状態にしておく。

ページングにかんしては後々実装するのでそこで触れる。

### 割り込み・例外の委譲

OSはSモードで実行するわけなので、割り込み・例外をSモードで処理するように振り分けている。

```d
    writeCsr!"medeleg"(0xffff);
    writeCsr!"mideleg"(0xffff);
```

ここでは `stvec` にはまだなにも登録していない。これも後々触れるので、ここではそういうものだとおもっておけばよい。

### Sモードへ

MPP・mepcのところで書いたように、Sモードに実際に切り替えるのは `mret` 命令である。
ここでは `hartid` と `dtb` が `a0` `a1` レジスタにくるように明示的に渡している。

```d
    __asm("mret", "{x10},{x11}", hartid, dtb);
```

ここから先がOSとしての機能となる。

なお余談として、このmretの下には実際に実行されることはないのだが、無限ループで `wfi` 命令で割り込み待ちを行っているコードがある。

```d
    while (true)
    {
        __asm("wfi", "");
    }
```

この関数は `noreturn` を使って戻ってこない関数を表していて、関数の実行フローに最後は無限ループを使うか `assert(0)` を使うかする必要がある。

-checkcontext=halt で `assert(0)` を使う場合、LLVMのintrinsic `llvm.trap` が使われ、最終的には `unimp` (不正命令)に落ちる。
こちらを使うのもありだが、将来的にassert関数を実装する余地を残すために今のところは無限ループで統一している。
